# ADR-0023: 日常的に使われるエージェントランタイム — 位置づけの見直しと cli-series への昇格

| 項目 | 値 |
|-------|-----|
| Status | **Accepted** |
| Date | 2026-09-26 |
| Binds | lagent |
| Decision makers | nlink-jp maintainers |
| Triggered by | 利用者の決定: 「lagent を lab から正式プロダクトへ昇格する」。根拠は日常的に使っていること。昇格先は RFP が想定した lite-series ではなく cli-series |
| Relates to | gem-agent ADR-0061（兄弟ランタイムでの同じ移動）、RFP §1・§3・§4・§6（本記録で改訂） |

## Context（背景）

RFP は lagent の憲章を実験として書いた。その前提は 5 箇所で荷重を負っていた:

1. **目的** — 「ローカル LLM でエージェントランタイムがどこまで実用になるかを …
   gem-agent と同じ物差しで検証する」（RFP §1）。README の冒頭、org プロフィールの
   行、Web サイトのカード、GitHub の About は、いずれも計測のために存在すると述べる。
2. **想定利用者** — 「当面は開発者本人。実験用途であり、配布は前提にしない」（RFP §1）。
   明示的な対象外一覧（§3）にも「配布・チーム利用（実験段階）」がある。
3. **状態** — README の「実験中（lab-series）」の注記。いまも Phase 2 を次の段階として
   記述している。
4. **シリーズ** — lab-series。「実用性が示せた時点で lite-series への昇格を再検討する」
   （RFP §6）。
5. **健全性チェック** — RFP §4 Phase 3 は「健全性チェック手順（gem-agent の drill
   相当）」を挙げる。作られていない。

前提の方が現実から外れた。Phase 2 は挙げた項目を圧縮以外すべて決着させた（圧縮は
実セッションが窓の半分を超える実例を待っている）。ADR は 22 本、署名・notarize 済み
アーカイブ付きのリリースは v0.10.2 まで、Homebrew formula があり、リスクレビュー 2 件に
対応した。そして利用者は lagent を実作業で日常的に使っている。憲章が求めた計測は
取り終え、残っているのは使われている道具である。

## Decision（決定）

**1. lagent は、クラウド API に出すべきでない作業のためのコーディングエージェント
ランタイムである。** その同一性は RFP の目的の行ではなく問題設定の方にある: オフライン
環境、機密プロジェクト、トークン単位の費用を掛けたくない作業を、gem-agent と同じ監査
可能な最小ループ（read / edit / shell / MCP / 承認）で、OpenAI 互換 API のローカル LLM
の上で担う。ベンチ（ADR-0006）は残る。ただし変更を決める計測器としてであり、
ランタイムが存在する理由としてではない。

**2. 昇格は即時。根拠は日常の利用。** 昇格基準が問うはずのこと — 実際に使えるか —
には実利用が答えている、というのが利用者の判断である。合格させるための基準を後から
書くことはしない。

**3. lite-series ではなく cli-series。** RFP §6 は再検討先として lite-series を挙げた。
lite-series の規約が描くのは、パイプラインで組み合わせる小さく単機能の道具で、対話 UI
を必要とせず、Linux・Windows・darwin/amd64 へクロスビルドし、環境変数は
`LITE_<PROJECT>_` を取る。lagent は TUI のエージェントで、設計上 macOS arm64 専用
（レーンは `sandbox-exec`）、環境変数は `LAGENT_*` である。lite-series に置けば、
これらの規則それぞれに対する恒常的な例外になる。cli-series には既に gem-agent —
同じ設計、同じプラットフォーム制約で、ツール別のビルド事情として既に記載済み — と、
lagent のバックエンドの系譜元であるローカル LLM クライアント llm-cli（ADR-0001）がある。

**4. 本日から cli-series の安定性契約が適用される。** 操作者に見える表面 — フラグと
サブコマンド、設定キー、`LAGENT_*` 変数、transcript と usage レコードの形式、hooks の
契約、skills と memory の置き場所 — は約束である。破壊的変更は CHANGELOG の 1 行では
なく、組織の破壊的変更プロセス（利用者確認 → 互換案 → 実装）を通す。0.x の版数も、
利用者が 1 人であることも、これを緩めない。契約があるから約束を誰でも検査できる。

**5. 健全性チェック手順は作らず、条件にもしない。** drill が存在する理由である環境の
劣化検知は、日常の利用が担う — gem-agent ADR-0061 が月次訓練を廃したときと同じ結論。
RFP の行は、ここを指す注記を付けて残す。

## Consequences（帰結）

- 位置づけを述べる面は、語句の差し替えではなく新しい前提から書き直す: README（両言語）、
  AGENTS.md、org プロフィールの行、Web サイトのカード（Experimental から AI Agents 節へ
  移動）、GitHub の About。RFP §1・§3・§4 Phase 3・§6 にはここを指す注記を置き、
  Discussion Log は歴史として残す。
- リポジトリは lab-series のアンブレラから cli-series のアンブレラへ移る。ローカルの
  パスは `cli-series/lagent` になる。リポジトリの URL とモジュールパスは変わらない。
  ランタイムの `internal/sandbox/lane.go` をパスで名指す組織の `check-org.sh` と、
  gem-agent の AGENTS.md の兄弟ランタイムの段落も移動に追随する。
- gem-agent との共有機構の規則（AGENTS.md: 両ランタイムにある機構の欠陥は両方で直す）
  は変わらない。両ランタイムは同じ契約の下に並ぶ。
- 受け入れるリスク: lab の間は表面が速く変わっていた。これからはフラグ・設定キー・
  レコード形式の変更に決定 4 のプロセスの費用が掛かる。それが意図した代価である。
- 歴史的な文書 — ADR 群、RFP の Discussion Log、リスクレビューの提出物、lagent を
  lab-series のランタイムと呼ぶ他リポジトリの RFP — は当時の文言のまま残す。記録は
  自分の時代を語る。
