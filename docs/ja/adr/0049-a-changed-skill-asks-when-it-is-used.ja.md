# ADR-0049: 変わったスキルは、使うときに尋ねる

| Ports | gem-agent ADR-0119 |

## Context

プロジェクトのスキルは内容でピン留めされ（ADR-0011 §6）、ピンはスキルの一覧を作るとき — 起動時と `/clear` のとき — に見比べられる。スキルの本文と補助ファイルは、`load_skill` や `/skill` が使うたびに、後からディスクから読まれる。そのときは何とも見比べない。

## Measurement

lagent v0.27.4、ローカルモデルを相手にした実セッション。プロジェクトのスキルを信用してピン留めし、セッションを起動してから `SKILL.md` を書き換えた。`!` コマンドの後の注記は、そのスキルを「変わった」と挙げた。続いて `/skill <name>` は書き換えた本文をモデルに送り、モデルはそれに従った。もう一度書き換えた後、モデル自身の `load_skill` 呼び出しは 2 度目の文面を返した。

セッションの途中でこのファイルを変えるのは、多くの場合は操作者自身である — `! git pull`、operator レーンのコマンド、別ウィンドウのエディタ。write レーンは `.claude` を拒否し、承認された書き込みは書いた 1 名を再ピンする。ただし操作者だけではない: プロジェクト内の別のディレクトリへのリンクになっているスキルは、名前で守られているので、リンク先への書き込みは普通の書き込みになる（設計の検証が file tool について実測）。MCP サーバーはサンドボックスの外で動く。いずれにせよ、誰も確認していない内容が、操作者自身の指示として読み込まれ、包まれずに送られる。

## Decision

1. プロジェクトのスキルの読み取りは、どれも先に見比べる。`load_skill`（本文と `file` の形）と `/skill` は、そのスキルのディレクトリを digest し、ディスク上の記録（`recordedPolicy`）と見比べる。ピンのための digest と、この見比べのための digest は、1 つの実装が、開いた root — ローダーが読む対象 — を通して取る。変わっていないスキルについて、両者が食い違うことはない。一致すれば、今までどおり読む。食い違うとき、または一覧にあるのに記録の集合に無いスキルは、2 の問いになる。ディレクトリが無くなっているのはエラーであって、問いではない。ピンが無効のとき、またはプロジェクトの記録が何も無いときは、何も見比べない。global のスキルは見比べない。
2. 問いは、ゲートの中の専用の問いである。読み取り専用の解除は、「この呼び出しを実行してよいか」ではない問いの前例である。この問いは、自分の答えを持つ。検証済みの名前でスキルを挙げ、そのディレクトリを示し、信用した時点から内容が変わっていること、または信用の記録にそのスキルが無いことのどちらかを述べ、中身を見るべきことを述べ、それぞれの答えが何をするかを述べる。信用すると、以後のセッションのためにもその内容を記録することを含む。答えは 信用する と 無効にする の 2 つだけで、ほかは出さない。常設の答えはこの問いに届かない: セッションの許可リスト、`"never"` のポリシー、自動承認、モデル層のいずれも答えられない。セッションの除外の集合も見ない: 一覧にあるスキルは、セッションが読み込んだスキルである。文面は、誰が変えたかを言わない。
3. 結果は 3 つで、ゲートはその 3 つすべてを返す: 信用した、無効にした、答えなし。どのゲートもこの問いを実装する — TUI、標準入力のゲート、単発実行のゲート。実装していないゲートは、答えなしとして読む。TUI では、Esc、Ctrl+C、ターンの中断が答えなしになる。標準入力のゲートでは、2 つの答えだけを数える: 空行やほかの文字列はもう一度尋ね、入力が閉じたら答えなしとし、ターンが中断された後に届いた答えは捨てる。
4. 信用する は、尋ねた対象を記録する。ディレクトリをもう一度 digest する。問いを起こした digest と違えば、何も記録せず、新しい状態についてもう 1 回だけ尋ねる。2 回目も違えば、その読み取りを答えなしとして断り、スキルがまだ変わり続けていると告げる。同じなら、その digest をその 1 名について、ポリシーファイルのロックの中で記録する — 期待する digest を受け取る専用の書き込みで行う — そして、その名前をセッションの除外の集合から外す。読み取りを実行し、もう一度 digest する: 違っていれば結果を捨て、同じように読み取りを断る。ピンは残す。それが、尋ねた対象である。
5. 無効にする は、そのセッションの間続く。答えは grant の隣にロック付きで持ち、`load_skill` と `/skill` が何よりも先に読む。書くのはゲートが答えた後だけで、ツールの中からは書かない。以後そのスキルを使おうとしても、尋ねずに断り、そのつど操作者に 1 行の知らせを出す。答えは、スキルの一覧を作り直すところでだけ忘れる。セッションの中で取り消すには、別のターミナルからの `lagent trust --accept` と `/clear` が要る。
6. 答えなし は、その 1 回の読み取りを断る。何も記録せず、何も無効にしない。次に使うときにまた尋ねる。
7. ターミナルの前に誰もいない場面では、何も尋ねない。判定は、起動時のピンの照合が使うものと同じにする。したがって単発実行もパイプ実行も読み取りを断る。拒否には専用の文面を使い、`lagent trust --accept` を挙げ、同じファイルを読み取りツールで読むようモデルを向かわせない。
8. `load_skill` は、拒否された資格情報の読み取りと同じ形で尋ねる（ADR-0016 §2）: ツールはスキルが食い違うと報告し、エージェントが、遅いツールを見切る床の外で尋ね、信用する ならツールをもう一度実行する。digest もダイアログも、ツール自身の実行の中には置かない。
9. `/skill` は、モデルの往復を使わずに、注入の前に尋ねる。見比べ、問い、読み取りは、ターン自身の goroutine へ移し、8 と同じエージェントの経路を通す。したがって、取り消されたターンはダイアログを出さず、結果は同じように記録される。信用する なら、ADR-0011 §5 が決めたとおり本文を注入する。無効にする、または答えなしのときは、モデルを呼ばずにターンを終え、そう告げる。
10. モデルに伝える文面は固定する。`load_skill` の結果は包まれずに送られるので、拒否はどれも、定数と検証済みのスキル名だけから作る — ディレクトリエントリの名前も、ファイルシステムのエラーも入れない。
11. ディレクトリは、ダイアログを書けない。ディレクトリエントリに制御文字を含むスキルは、注記を付けて、一覧に載せない。問いはディレクトリを引用符で囲んで示し、その文面はどちらの画面でも無害化する。
12. 結果はすべて、専用の種類で記録する: 問い、結果、断った繰り返しのそれぞれを、スキルの名前とともに。ゲートの判定としては記録しない: 信用する の答えは、呼び出しの承認ではない。
13. `load_skill` の説明と、これを「ゲート無し」と呼ぶコメントを、実際に合わせる。

## What differs here

- スキルの一覧を作り直すのは `/clear` だけである: スキルの reload は無く、`/mcp reload` はピンを照合し直すが一覧は作り直さず、新しいセッションを開けずにその場で消すだけになった `/clear` は何も作り直さない。無効にする の答えは、一覧を作り直すところでだけ忘れる。
- 無効にしたスキルは、既に送った facts メッセージの一覧の行に残る（ADR-0003: そのメッセージは会話の一部である）。そうでないことをモデルに伝えるのは、拒否の文面である。システムプロンプト、ツールの集合、facts メッセージは、バイト同一のままである。
- モデル層（ADR-0032）は、操作者だけが答えられる判定を扱わない。2 は、モデル層が既に従っているその規則によって、これを除外する。
- 子エージェントも、テレメトリも、ルールの学習も無い。上の各項は、このランタイムが持つものだけを挙げている。

## Consequences

- 「使う前に見比べる」が、スキルについて、使う時点で成り立つ。スキルに触れる `git pull` の後、最初に使うときに 1 回、セッションの中で尋ね、操作者はキー 1 つで答える。
- プロジェクトのスキルの読み取りは、前にディレクトリの digest を 1 回、信用する と答えた後はさらに 2 回取る（上限: 2,000 ファイル、各 1 MiB）。実装を完了とする前に、入っているうち最大のスキルで測る。
- これはダイアログ 1 つの変更ではない。ゲートの契約に、3 通りの結果を返す問いが、すべての実装で加わる。2 つの画面にダイアログが加わる。`/skill` は文字列の展開でなくなり、ターンの 1 段になる。ピンの digest は root の上へ移る。設計の検証は、読み取り専用の解除と資格情報の再試行を合わせた大きさと見積もった。それを知ったうえで選んだ: 得られるのは、変わったスキルが確認なしに読み込まれることがなく、別のターミナルも要らない、ということである。
- 問い、2 つの答えのラベル、ヒント、知らせは、両言語のカタログに入れる。拒否はモデル向けで、固定である。
- ADR-0011 §5 は変わらない: `/skill` はモデルの往復を使わない。

## Tests the design requires

- 読み取りの箇所（`load_skill` の本文、`load_skill` の `file`、`/skill`）を列挙するテストを 1 つ置き、見比べずに読む箇所があれば落とす。
- 変わっていないスキルについて、使う時点で取る digest がピンの digest と等しいことを、ピンが区別する場合（リンク、1 MiB を超えるファイル、上限を超える数のファイル）にわたって確かめるテストを 1 つ置く。
- ピンが有効で記録もある状態で、変わったスキルが、本番の配線を通って問いにたどり着くことを確かめるテストを 1 つ置く。つながっていない配線は「一致」と同じに見える。
- ゲートの実装ごとに、返しうる 3 つの結果のテストを置く。Esc、中断、空行、閉じた入力を含む。
- 3 つの結果と、無人の場面での拒否のそれぞれについて、何が記録され、モデルが何を受け取り、何が無効のまま残り、その後に除外の集合が何を持つかをテストする。
- 4 の窓は、問いと答えの間で 2 回、ピンと読み取りの間で 1 回、ディレクトリを変えてテストする。
- 制御文字を含むディレクトリエントリが、一覧に載らないことをテストする。

## Accepted, and written down

- 同じ名前の操作者自身のスキルは、無効にした後も、`/clear` まで隠れたままになる。ADR-0011 §6 は一覧を作るときにそれを戻す。ターンの途中で行うと、動いているターンの下で一覧を差し替えることになる。
- digest には限界がある: 2,000 番目より後のファイルは覆わず、リンクはターゲットの文字列で、1 MiB を超えるファイルの内容は大きさだけで覆う。
- スクリプト。スキルを読み込んだ後でスクリプトが変わると、シェルはそこにあるものを、すべてのコマンドに共通のレーンと承認の規則の下で実行する。
- ほかの読み手。読み取りツールと `@` の参照は、スキルのファイルをデータとして、包んで読める。変わる前に読み込んだ本文は、会話に残る。
- 失われた記録。ポリシーファイルがこのプロジェクトのピンを持たなくなっているとき、信用する の答えは、その 1 名だけの集合を記録する。
- `/clear` は、これまでどおり、変わったファイルを外して名前を挙げる。指示ファイルには、守るべき後からの読み取りが無い。
- 変わり続けているスキルは、もう 1 回尋ねた後で断る。pull やビルドが終わってから、操作者があらためて使う。

## Alternatives considered

- 尋ねずに拒否し、操作者に別のターミナルから信用し直させる。安全側に倒れ、より小さいが、セッションの中で答えられる問いのために、操作者をセッションの外へ行かせる。
- 理由の行を付けた通常の承認ダイアログ（最初の草稿）。「このセッション中は許可」と「今後は尋ねない」を出してしまい、ここではどちらも、信用する に加えて、どこにも見えない常設の項目を作る。また、ターンを中断すると いいえ と答えたことになり、誰も無効にすると決めていないスキルが無効になる。どちらも設計の検証が見つけた。
- `/skill` がモデルに `load_skill` を呼ぶよう伝える（最初の草稿）。ADR-0011 §5 が使わないと決めたモデルの往復を使う。モデルが呼ばなければ、何も読み込まれず、何も告げられない。
- パイプの 1 行を答えとして受け取る。ADR-0045 はパイプを操作者の入力とし、標準入力のゲートは次の行を読む。しかし起動時のピンの照合は、同じ実行を「尋ねる相手がいない」として扱っている。
- 一覧を作る時点で読んだ本文を持ち続ける。補助ファイルとスクリプトは後から読まれるので、スキルが半分古く半分新しくなる。
