# ADR-0004: MCP ツールはモデルが先に読む目録から、必要なときに広告する

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-09-10 |
| Binds | lagent |
| Decision makers | nlink-jp maintainers |
| Triggered by | ADR-0003 で接頭辞キャッシュは新セッションを生き延びるようになったが、サーバ再起動後の最初のセッションは今もツールブロック全体を払う: MCP 243 ツール、60,097 トークン、参照機で約 2 分 — そして 26B モデルが 243 スキーマから選ぶ精度は誰も測っていない |

## Context

全リクエストが、接続した全 MCP サーバの全ツールを function スキーマとして
広告する。操作者の global `mcp.json`（23 サーバ）では 243 スキーマ、
会話の一語も無い段階で 60,097 トークン。3 サーバ（slack-extender、github、
obsidian）でその半分を占める。組込ツール（ファイル・シェルの 8 つと
`ask_user`）は 9 スキーマ、約 2,500 トークン。

ADR-0003 はこのブロックをセッションをまたいでキャッシュ可能にした。小さく
はしていない: サーバのキャッシュはプロセス単位で収まる分だけ保持し、
LM Studio 起動後の最初のセッションは全量を払い、モデルはタスクが触れるか
どうかに関わらず毎ターン 243 スキーマを読む。ローカルモデルではどちらの
コストも構造的だ — 約 580 トークン/秒のプロンプト処理と、呼ばない 200 の
ツールに分散する注意。

今日ある手段は `[mcp].exclude`: 操作者がプロジェクトごとに手で集合を削る。
それはセッションがどのサーバを要するかを操作者に予測させるもので、
ランタイムの方がその推測を避けるのに向いている。

RFP は `.mcp.json` の drop-in 読み取りを保つ: サーバの集合は操作者の
Claude Code 設定そのままである。この記録が変えるのはモデルに見せるもので
あって、接続するものではない。

## Decision

MCP サーバは今日どおり接続し、ツールは今日どおり登録する（`mcp__<server>__<tool>`、
`[mcp].exclude` で濾過、同じ階梯でゲート）。ただしサーバがロードされるまで
モデルには**広告しない**。モデルが見るのは:

1. **ランタイム事実メッセージ内の目録**（ADR-0003 の経路。system プロンプト
   ではない）: 接続したサーバごとに 1 行 — 名前、ツール数とツール名、
   `initialize` で公開した `instructions` の最初の一文（切り詰め）。
   目録はセッション状態（どのサーバが立ち上がったか）そのもので、事実
   メッセージが運ぶべきものである。system プロンプトと広告するツール
   ブロックは MCP 設定が何であれバイト同一に保たれる。
2. **組込ツール 1 つ、`mcp_load`**。サーバ名を取る。そのサーバの登録済み
   ツールをセッションの残りの間広告し（拡げた集合で `Agent.RefreshTools`）、
   一行の一覧を返す。読み取り専用で Safe: サーバは既に走っており、ロード
   しても何も実行されない。未知の名前と除外された名前は目録の綴りを添えて
   拒否する。
3. ロード後、そのサーバのツールは登録名で、チャットテンプレートが描画する
   スキーマを伴って**ネイティブに**呼ばれる — 描画されたスキーマから 26B
   モデルが得る引数の規律こそ、これがロードであって `mcp_call(server, tool,
   json)` プロキシでない理由である（Alternatives 参照）。

契機は、能力の契機が置かれるべき場所に書く: 目録の行が「先に `mcp_load` を
サーバ名で呼ぶ。するとそのツールが現れる」と言い、不変の system プロンプトは
「MCP サーバはランタイム事実メッセージに列挙され、必要に応じてロードされる」
という一般文を 1 つ言う。「〜するな」は書かない — スキーマの不在が制限の
全てである。

操作者の制御:

- `[mcp].preload = ["tor-exit-lookup", …]` は名指ししたサーバを最初から
  広告する。毎セッション使う lookup 向けで、キャッシュは組込ツール同様に
  それらを保持する。
- `--allow mcp__<server>__*` はどのモードでもそのサーバをプリロードする: 許可
  はその実行が必要とするという操作者の宣言であり、パイプラインはモデルが
  ロードを思い出すことに依存してはならない。
- `[mcp].advertise = "all"` は今日の挙動を復元する — 計測のベースライン、
  比較実行での gem-agent 同等性。
- `/mcp` は各サーバのロード状態を示し、`/mcp load <server>` は手でロードする。

永続化: ロードは transcript にそのままのツール呼び出しとして記録される。
`--continue` / `--resume` ではランタイムが見つけた `mcp_load` 呼び出しを再生し、
それらのサーバを再び広告するので、再開したセッションは見たものを見る。
`/clear` は未ロードで始まり、新しい事実メッセージに新しい目録が乗る。

会計: usage レコードに新フィールドは要らない — 節約はラウンドごとの `prompt`
トークンとして、gem-usage-lens でベースラインと並ぶ。

## Consequences

- cold の接頭辞は操作者の設定で約 63k トークン（組込 + MCP 243 スキーマ）
  から約 4k（組込、`mcp_load`、サーバごとの目録行）へ落ちる — 2 分の最初の
  セッションが 10 秒程度になり、キャッシュは救済ではなく上乗せになる。
- ロード 1 回は接頭辞の再処理 1 回分: ロードしたスキーマとそこまでの会話。
  ツールブロックは会話に先行するからだ。セッション早期なら数秒。
  `[mcp].preload` は操作者が常に欲しいサーバをキャッシュ側へ移す。
- モデルはタスク相応のツール集合を見る。26B モデルが 23 行の目録から正しい
  サーバを選べるかは、この記録が可能にする計測項目そのもの。ベースラインは
  `advertise = "all"`。
- ツール呼び出しの記録、`[approval.tools]` のパターン、`--allow`、
  `[mcp].exclude`、規則層の `mcp__` 扱い、承認プロンプトは不変: ロード後の
  モデルの呼び出しは今日と同じ `mcp__<server>__<tool>` 呼び出しである。
- 操作者向けに増えるのは 2 つ: 事実メッセージの目録行と、`/mcp` のロード
  マーカー。バナー行は増えない。
- 移植元 gem-agent は同じブロックを Vertex への全リクエストで課金対象の
  入力トークンとして払っている。この設計はそのまま移植でき、本家への提案に
  値する。その提案はこの記録の拘束外。

## Alternatives considered

- **スキーマをテキストで取得する `mcp_call(server, tool, arguments)`
  プロキシ** — ツールブロックを永久に一定に保つが、モデルはテンプレートが
  描画するスキーマではなく読んだ散文から引数を書くことになり、ローカル
  モデルの引数の規律はテンプレートを最も必要とする部分。却下。ロードが
  実運用でキャッシュを荒らすと分かれば再検討。
- **手で集合を削る**（`[mcp].exclude`、今日）— 引き続き使え、これと合成
  できる。唯一の答えとしては、操作者にセッションの予測を求めるので却下。
- **system プロンプト内の目録** — 設定が同じなら不変だが、起動に失敗した
  サーバやプロジェクトの `.mcp.json` がそれを変えてキャッシュを壊す。
  セッション状態が住むのは事実メッセージ。却下。
- **初回呼び出しでロード**（モデルが未提示の `mcp__server__tool` を呼び、
  ランタイムがミスでロード）— スキーマを与えられていないツールを推測なしに
  呼ぶことはできず、推測した呼び出しがサーバに届くのは承認ゲートが止める
  ために存在する失敗形。却下。
- **全部広告してキャッシュに頼る**（ADR-0003 のみ）— この記録以前の状態。
  `advertise = "all"` のベースラインとして残す。
