# ADR-0012: pre-tool フックはモデルの外にある操作者の制御

| 項目 | 内容 |
|------|------|
| ステータス | **Accepted** |
| 日付 | 2026-09-12 |
| 拘束対象 | lagent |
| 決定者 | nlink-jp maintainers |
| きっかけ | 操作者: hooks はここにもあるべきだ — モデルが暴れるとき、サンドボックスと並んで、モデルが聞いているかに依存しない防御になる |

## 背景

サンドボックスはレーンが触れるものを決める: read レーンはプロジェクトを
書けず、どのレーンも資格情報のパスに届かず、操作者専用ファイルは常に
尋ねる。だが命令をその形で拒むことはできない。操作者が承認したばかりの
write レーンでの `gofmt -w .`、あるいは規則層がプロジェクト内書込を Safe
と呼ぶ `--auto` 下でのそれは、サンドボックスが引くあらゆる境界の内側で
ワークスペース全体を書き換える。組織はまさにこの種別（相対パスに向けた
再帰的なその場書き換え）に対して Claude Code の `PreToolUse` ガードを
運用しており、その根拠は「書かれた規則は注意の途切れを防げないので、制御は
エージェントの外に置く」である。gem-agent はフォールバック時にもそれが
生き残るよう同じガードを備える（gem-agent ADR-0044）。lagent にはこれまで
無く、しかもこのランタイムのモデルは散文で最も操縦しにくい（ADR-0008:
ここではプロンプトの規則は制御ではない）。

このランタイムが既に計測したことが形に効く:

- **理由付きの拒否はモデルを導く。** ADR-0008 下で無人の拒否は経路を名指し、
  ベンチはモデルがそれを取ることを示した。ツール結果として返るフックの
  理由は同じ機構である。
- **拒否された呼び出しの繰り返しはラウンド階梯が捕まえる。** 同一呼び出し
  3 連続はエスカレートし、無人ならターンを止める。呼び出しを拒むフックと
  固執するモデルは、したがって 3 ラウンド以内にループガードで出会う。
  それが操作者の言う「暴れる」場合で、モデル層無しに閉じる。
- **ツール結果はデータ**（RFP §3）。フックは設定されたコマンドで、その言葉を
  プロンプトで誰も検分しない。だからその理由はスキル（ADR-0011）のように
  包まずにではなく、他の結果と同じく包んで届く。

gem-agent のフック契約は文書ではなく計測で得た: インストール済みガードは
Claude Code の PreToolUse stdin JSON から `tool_input.command` を読み、
stdout に `hookSpecificOutput.permissionDecision: "deny"`、exit 0 で答える。
`shell_exec` はここでもあちらでも引数を `command` と呼ぶので、組織の
ガードは lagent のペイロードでそのまま動く。

## 決定

1. **イベントは 1 つ、lagent 自身の設定から、global のみ。**
   `config.toml` の `[[hooks.pre_tool_use]]` エントリが `matcher`、`command`、
   任意の `timeout_sec` を持つ。`~/.claude/settings.json` は読まない
   （ADR-0011 の原則: 形式は drop-in、置き場所は共有しない）。プロジェクト
   ファイルはフックを登録できない: クローンしたリポジトリがツール呼び出し
   ごとに任意のコマンドを走らせることになる。Claude Code の他のイベントは
   実装しない。消費者が現れたとき同じ機構が受け入れ（gem-agent ADR-0069 は
   agent-board のために 2 つ足した）、それは固有の記録になる。
2. **拒否は床。** フックはツール dispatch の先頭、広告チェックの後・決定の
   梯子の前で走る: 自動承認も `"never"` 行も `--allow` もセッション
   許可リストも覆せない。理由はツール結果としてデータに包んでモデルへ行き、
   transcript は理由付きの `hook_denied` を記録する。フックが守るのは
   モデルの呼び出しだけ: 操作者の `!` エスケープは通らない。
3. **判定は両形式。それ以外は注記付きで fail open。** フックは stdout JSON
   （`hookSpecificOutput.permissionDecision: "deny"` または古い
   `decision: "block"`）か、stderr を理由とする exit code 2 で拒む。非ゼロ
   終了、解釈不能な出力、タイムアウトは呼び出しを梯子へ進め、操作者の前に
   警告を 1 行置く: フックは締めるだけで、壊れたガードがランタイムを
   止めてはならない。フックはサンドボックス外、プロジェクトディレクトリで、
   既定 10 秒のタイムアウト、自身のプロセスグループで走り（タイムアウトは
   起動した子も殺す）、両ストリームは到着時に上限で切る。
4. **matcher は両方の語彙を話す。** 厳密なツール名、`|` 選択、`*` を、
   lagent の名前とその Claude Code 別名（`Bash`、`Write`、`Edit`、`Read`）の
   両方に照合する。Claude Code 設定から複製した hooks ブロックが改名無しで
   動く。ペイロードの `tool_name` は lagent の実名。
5. **ペイロードは Claude Code の PreToolUse 形**に、Claude Code の全イベント
   が運ぶセッション識別を添えたもの: `hook_event_name`、`session_id`、
   `transcript_path`（ログ無効時は空）、`cwd`、`tool_name`、`tool_input`。
   `tool_input` はモデルが送った引数から宣言済み purpose を除いたもの
   （フックは裁き手で、提案者の自己正当化は証拠ではない）。`shell_exec`
   ではレーン `access` を含む — ここのガードは命令だけでなくレーンでも
   判定できる。

## 結果

- 組織の書き換えガードと削除規則がこのランタイムでも効き、Claude Code と
  gem-agent が走らせるのと同じスクリプトファイルで強制される。登録は同じ
  ファイルを指す lagent 設定の 1 ブロックで、複製は無い。
- モデルのツール呼び出しごとに matcher 比較 1 回、一致した呼び出しは
  プロセス起動 1 回。未設定なら何も走らない。
- フックは全てを拒める（可視の denial of service）が、何も承認できない。
- フックが拒んだ呼び出しにモデルが固執する無人実行はループガードで止まる —
  ADR-0010 が既にこのランタイムに述べた fail-closed の天井で、今は
  transcript にフックの理由が残る。
- `internal/hooks` は gem-agent のパッケージの移植（doc コメントに元
  コミット、ADR-0001）をこの 1 イベントに削ったもの。`agent.Options` に
  `PreToolHook` が加わる。設定リファレンスと同梱テンプレートに `[hooks]`
  節 1 つ。設定パネルの行は無い — トグルのある制御はバイパスである。

## 検討した代替案

- **`~/.claude/settings.json` を読む。** 却下: Claude Code の設定が変わる
  たびにランタイムのガードが変わり、設定ファイルは hooks 以外を多く運ぶ。
  ADR-0011 と同じ原則。
- **Claude Code の全イベントを一度に。** 却下: 消費者が示されたのは 1
  イベント。他は現れるまで死重で、それぞれに決めるべき配送規則がある
  （gem-agent ADR-0069 §4 は文脈フックの出力の置き場に 1 ページ使った）。
- **プロンプト規則（「`.` への再帰的書き換えを走らせるな」）。** ADR-0008
  とガード自身の根拠で却下: モデルが覚えるべき規則は、モデルが聞くのを
  やめた瞬間に失敗する。制御はモデルの協力を要してはならない。
- **規則層の Block 床にパターンを足す。** 却下: 規則層は意図のために命令
  テキストを読まない（gem-agent ADR-0073。レーンが決める）し、その Block
  一覧はランタイムの有限の床。操作者のガードは操作者のもので、操作者の
  言葉で書かれ、リリース無しに変わる。
