## Context

セッションのルートは、プロジェクトとセッション作業ディレクトリの 2 つです。サンドボックスが有効なとき、その外の木には一切書き込めず、ファイルツールは読み取りさえ拒みます。唯一の道は `--no-sandbox` で、セッション全体のすべての保護を手放すことになります。ノート、Vault、隣のチェックアウトをプロジェクトの横に置いている操作者には、中間の手段がありません。

gem-agent は、3 回のレビューを経た設計と、実測した失敗の一覧でこれを塞ぎました。このランタイムはレーン、ファイル読み取りの子プロセス、判定、永続ファイルの監視を共有しているので、その設計を受け取り、ここでは違えなければならない点を述べます。

## Decision

振る舞いは gem-agent ADR-0099 の各節のとおりです。要約すると次のとおりです。

1. **追加ディレクトリはレベルを持つルートである。** `read` はファイルツールと read レーンが読み、operator レーンを含めどのレーンも書きません。`write` は `read` に加えて、ファイルツールと write・operator レーンがプロジェクトと同じように書きます。資格情報のフィルタ、永続ファイルの名前、`.git` への書き込みの扱いは、どのルートでも保たれます。
2. **中身は何も読み込まない。** 指示、サーバ、ポリシー、スキルのいずれも読み込みません。
3. **操作者が追加する。** `--add-dir` / `--read-dir`（繰り返し可）、グローバル設定ファイルの `[directories].write` / `.read`、プロンプトでの `/add-dir` / `/read-dir` です。`/dirs` はルートを一覧します。引数なしの `/add-dir` や `/read-dir` も同じです。プロジェクトの `.lagent.toml` では追加できません。`LoadProject` がそのテーブルを未知のキーとしてすでに拒否します。
4. **判定する規則は 1 つ。** `sandbox.RefuseRoot` は、`/`、ホーム、プロジェクト・作業ディレクトリ・設定ホーム・状態ディレクトリを含むもの、後の 2 つの内側、資格情報の場所、共有の一時ディレクトリ、`/dev`、そして write については使用中の設定ファイルと `~/Library`（同期フォルダ、つまり `~/Library/CloudStorage` の厳密に内側と iCloud Drive を除く）を拒否します。判定するのはカーネルが返すパス名です。起動時に拒否されたら起動を止めます。
5. **ルート集合を使う箇所はすべて追加ルートを知る。** レジストリ（ルートごとに `os.Root` を持ち、read ルートへの書き込みは判定の結果によらずここで拒否する）、ファイル読み取りの子プロセス、`risk.Classify`、リスクレビュアーのペイロードと規則、`@` メンション、`Agent.intoRoots`、プロファイルの `Spec` と `/clear` での再構築、そしてルートを名指すすべての文言です。
6. **プロファイルの順序も規則の一部である。** 追加ルートの読み取りの再許可は `writeCredentialBlock` より前に置き、これが最後の読み取り規則であることを保ちます。追加ルートごとに、起動時とすべての付与時に、実際のプロファイルでプローブを走らせます。
7. **write ルートの永続ファイルは監視して報告する。** `trustpin.Snapshot` で、起動時、`/clear`、終了時に行います。止めはしません。
8. **付与の経路は 1 つ。** 操作者のコマンドもモデルの要請も同じ関数を呼びます。判定し、開いて実パスを読み戻し、付与ロック（`/clear` と共有）を取り、構築してプローブし、スナップショットを取り、差し替えて、記録します。検証に失敗したら付与を拒否し、セッションは元のままです。付与がサンドボックスについてランタイムが確立した状態を変えることはありません。入力したパスがリンクを経由して解決される場合は何も追加せず、実パスを示します。付与はプロセスの間だけ有効で、ファイルには書きません。

### ここで違えること

1. **モデルはルートをシステムプロンプトではなく事実メッセージから知る。** ADR-0003 はシステムプロンプトをセッションをまたいでバイト単位で同一に保ちます。ローカルサーバでは、そのどこかが変わると前置き全体を再処理するためです。`sessionFacts` は追加ルートごとに 1 行をレベルつきで載せ、そこにある指示ファイルはデータであると述べます。システムプロンプトは変えません。
2. **付与は次のターン境界で新しい事実メッセージとして伝える。** `AnnounceSession` は追記するので、`/mcp reload` と同じく手前の前置きはキャッシュされたままで、圧縮器もほかの事実メッセージと同様に運びます。`AnnounceSession` はターンの間でしか呼べないので、付与は事実を古いと印づけるだけで、要請のツール結果がモデルにすぐ伝えます。付与の費用は事実メッセージ 1 通分で、付与したときにしかかかりません。
3. **`request_directory` は ADR-0008 の理由で残す。** ルートの外のパスを拒否されたローカルモデルは、今は文章で終わってしまいます。このツールは、操作者が必ず答える経路を与えます。どのモードでも `OperatorOnly` で、セッションの許可リスト、ポリシー、リスクレビュアーでは答えられず、`-p` では登録されず、`Subset` にも入りません。対話セッションのツール一覧に固定のスキーマが 1 つ増えます。
4. **1 回の変更として出す。** gem-agent は起動時とセッション中の付与を 2 つのリリースに分け、後者をレビューで直しました。ここでは、その修正を入れた形で一緒に入れます。
5. **名前はこのランタイムのものにする。** 設定ホームは `~/.config/lagent`、状態は `statedir` 経由、プローブのディレクトリは `.lagent-root-probe-*`、監視の状態は `persistent.json` の隣の `added-persistent.json` です。
6. **承認レーンのキャッシュに専用の規則は要らない。** 状態ディレクトリの下にあり（ADR-0042）、`RefuseRoot` はそこをどのルートにも入れません。read レーンでの名指しの拒否も、すべての許可の後ろのままです。
7. **同じ場所を指すパスの比較は `pathid` を通す（ADR-0035）。** 付与の中でカーネルが返した 2 つの名前を比べる箇所は、gem-agent のレビューが求めるとおりバイト単位のままにします。大文字小文字を区別するボリュームでは、大文字小文字だけの入れ替えも変化だからです。

### 実装の順序

1. サンドボックス: `AddedRoot`、プロファイル、`RefuseRoot`、`CanonicalDir`、プローブ。
2. 利用側: レジストリ、子プロセス、判定、レビュアー、メンション、`intoRoots`。
3. 起動: 設定、フラグ、事実メッセージ、監視。
4. 付与の経路、スラッシュコマンド、`request_directory`。

各段を、テストつきの 1 コミットにします。gem-agent ADR-0099 §12 が挙げるテストはコードとともに移植します。

## Consequences

- Vault、ノート、隣の木を、`--no-sandbox` なしでレーンの下で読み書きできます。
- 広いディレクトリへの `write` を承認すると、自動承認の下ではそこへの以後の書き込みは確認されません。それが付与の意味であり、確認画面にもそう書きます。
- **残余: write ルートには永続ファイルを置けてしまい、拒否ではなく報告で済ませる。** write レーンのコマンドは `d/AGENTS.md` をスクラッチで作って `d` ごとルートに移せます。その下で後から始めたセッションは、それを祖先のファイルとして読み込みます。報告が届くのは、そのルートを追加したプロジェクトのセッションだけです。止めるにはルートへの改名をすべて拒否するしかありません。エージェントで開くプロジェクトの親にあたるディレクトリを write ルートにしないでください。
- **残余: 追加ルートの中の走査にはプロジェクトの無視規則が効く。** 作業ディレクトリと同じです。
- **残余: write ルートにはほかのプログラムが実行するファイルが含まれうる**（`~/bin`、シェルの設定）。操作者はパスを見て決めており、そうした場所の一覧は陳腐化します。
- **残余（gem-agent のレビューから）:** `os.OpenRoot` は `O_NONBLOCK` なしで開くので、判定と open の間にルートが FIFO に差し替えられると付与は止まります。その差し替えができるのは、どのレーンの外にもいるプロセスだけです。
- 付与のたびに `sandbox-exec` のプローブが数回走ります。
- 再開したセッションは、フラグと設定から始め直します。`/dirs` で有効なものを確認できます。

## Alternatives considered

- **gem-agent のようにルートをシステムプロンプトに書く。** 却下: この機能を使うすべてのセッションで ADR-0003 を破り、セッション中の付与で前置き全体を再処理することになります。
- **クラウド向けの機能として `request_directory` を外す。** 却下: 費用はスキーマ 1 つで、無いとモデルには文章で終わる以外の経路がありません。
- **付与の後に事実メッセージ全体ではなく短い差分メッセージを送る。** 却下: 圧縮器が運ぶのは事実メッセージなので差分は落ち、圧縮の後にモデルがルートを見失います。
- **スラッシュコマンドだけを足す。** 却下: コマンドはルート・判定・プローブへの薄い入口で、機能の本体はそちらです。
