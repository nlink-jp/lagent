## Context

**ルートの外のリンクを通したパス。** ルート — プロジェクトとセッション作業
ディレクトリ — は実パスである。`Registry.resolvePath` は、リンクを解決する前に、
打ったパスが*字面の上で*ルートの中にあるかを確かめる。だから、どのルートの外にも
あるリンクを通して打ったパスは、解決される前に断られる。このマシンで測った
（2026-11-06）。両方のルートの外にあるディレクトリに置いたリンクで:

| 打ったパス | `RealPath` | ルールの段（`write_file` の判定。`read_file` は読み取り専用で Safe） | `write_file` | `read_file` |
|---|---|---|---|---|
| リンク → プロジェクト、既存のファイル | 断る | Block、「outside the project and session work directories」 | 断る、「path escapes the project directory」 | 断る |
| リンク → プロジェクト、新しいファイル | 断る | Block | 断る | 断る |
| リンク → 作業ディレクトリ | 断る | Block | 断る | 断る |
| リンク → 両方の外 | 断る | Block | 断る | 断る |

これに当たるのは、クラウドストレージにあるプロジェクトである: 運用者が
`~/Library/CloudStorage/Dropbox/proj`（起動時にランタイムが解決する実パス）を開き、
リンクを通した完全なパス `/Users/<名前>/Dropbox/proj/…` を打つか、モデルがそう書く
（`~` で書いたパスは、ファイルツールが展開しない。この ADR の前も後も）。シェルのレーンは影響を受けない。
カーネルがリンクを解決する。

**自分のファイルを消せなかったプローブ。** `VerifyReadLane` と `VerifyWriteLane` は、
起動のたびにプロジェクトにプローブのファイルを作り、消すときの失敗を無視する
（`internal/sandbox/lane.go` で読んだ。ここでは測っていない）。運用者の役割が
「作れるが消せない」共有ドライブにあるプロジェクトでは、`.lagent-lane-probe-*` の
ファイルとプローブ用のディレクトリが残り、ドライブを共有している全員へ同期され、
何も言われない。

gem-agent は、独立した設計レビュー・実装レビュー・リリース前レビューを経て
両方を決めた。この ADR は、レビューが置き換えた途中の案ではなく、リリースされた
とおりの決定を取る。

## Decision

### 1. パス引数は、呼び出しが入ってきたところで一度だけ書き換える

ツール呼び出しが入ってきたとき — 表示し、判定し、フックに渡し、実行し、監査する
前に — 組み込みのファイルツールのパス引数を一度だけ見る: `read_file`・
`write_file`・`edit_file`・`view_image`・`show_image`・`file_info`・`list_files`・
`list_tree`・`search_files` の `path`、`write_file` の `from`、`file_info` の
`paths` の各要素。ほかのツールには触れない。絶対パスで、字面の上で両方のルートの
外にあり、綴りの上で資格情報ではなく、マウントの木の中でもない引数は、その**親**を
解決する。解決した親と、打ったとおりの最後の要素をつないだものがルートの中に
あれば、引数をそれに置き換える。自分のリンクで名指したルートは、そのルートになる。
それ以外は打ったとおりのままで、あとで今とまったく同じに断られる。

解決はパスを 1 要素ずつ、すでに実パスである接頭辞につないで進み、その接頭辞を、
中を読む前にマウントの木（`/Volumes`・`/Network`・`/net`・`/home`。
`/System/Volumes/Data` の下の綴りも、大文字小文字を畳んで）と照らす。だから、
どんな綴りやリンクの連鎖を通しても、承認の前に共有に触れない。

書き換えた呼び出しが、それ以降の呼び出しである。履歴にあるモデル自身の
メッセージは、送ったままにしておく。理由は gem-agent ADR-0108 のとおり: 判定と
実行が 1 つの文字列を読むので、その間にリンクを見ない。親だけなので、最後の要素の
リンクは引き続き実名で判定し、置き換えで書く。綴りで判定する床は綴りを保つ。
失敗しても、リンクがどこへ行くかを言わない。

`@` 参照も、絶対パスの参照について同じ規則に従う。

### 2. プローブの消し残しを知らせる

レーンのプローブ — プロジェクト・ホームの直下・`/private/tmp` に作るファイル — は、
消せなかったプローブのファイルをパスで、起動時の注記と
して知らせる（レーンを作り直す `/clear` でも）。運用者への注記である。lagent には、
モデルがエラーを読むことになるセッション途中の付与が無い。

### 3. 移植するコード

`sandbox.IntoRoot`、その歩み方とテストは gem-agent `e42f89e` の
`internal/sandbox/intoroot.go` から、追加したルートを取り除いて持ってくる。移植元の
コミットはファイルのドキュメントコメントに記録する（ADR-0001）。

## Consequences

- ファイルツールが、運用者やモデルが知っているリンクの名前で、プロジェクトと
  作業ディレクトリに届く。
- 新しい到達範囲は無い: 書き換えが作るのはいつもルートの中のパスで、ファイル
  ツールはそれを、打たれた実パスと同じに閉じ込める。
- 受け入れる残余は gem-agent ADR-0108 と同じ: 承認前に、ルートの外にある親の
  メタデータを読む（保護されたフォルダでは macOS が尋ねることがある）。解決は承認の
  前に、ターンの取り消しなしに走る。`~` は展開しない。
- マウントの木の中にあるプロジェクト（`/Volumes/…`）には、リンクを通しては
  届かない: 歩みは中を読む前にマウントの木で止まる。実パスは今までどおり使える。

## Alternatives considered

- **lagent には追加ディレクトリが無いので、何も移植しない。** 却下: どちらの欠陥も
  lagent がすでに持つコードにあり、クラウドストレージにあるプロジェクトは今日
  1 つ目に当たる。
- **`resolvePath` で、使うたびに解決する。** gem-agent の設計レビューで却下: 判定と
  実行が別々に解決することになる。
