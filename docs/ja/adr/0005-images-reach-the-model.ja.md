# ADR-0005: 画像はモデルに届く — ドロップされたパスは添付、view_image は復帰、無いファイルは言う

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-09-10 |
| Binds | lagent |
| Decision makers | nlink-jp maintainers |
| Triggered by | 入力欄に貼られたスクリーンショットのパス（端末へのドロップが生む形）が何も添付せず、モデルは画像を受け取ったと言い、次に見てもいない中身を描写した |

## Context

操作者はスクリーンショットを端末にドロップした。macOS はファイルの絶対
パスを、空白を全てバックスラッシュでエスケープして貼り付ける。操作者は
それをバッククォートで囲んで送った。何も添付されなかった: `@` 文法が
唯一の添付経路で、仮に `@` があっても最初のエスケープ済み空白で止まる。
モデルは画像があるかのように答え、次の質問では見たことのない Python の
エラーを描写した。

同じ入力を gem-agent（Gemini 3.8 flash）に与えると正しい描写に至ったが、
経路はツール呼び出し 7 回だった: パスへの `ls`、プロジェクト外で失敗する
`view_image`、write レーンでの操作者ファイルのプロジェクト内への `cp`、
複製への `view_image`、そして `rm`。モデルが添付の欠落を回避できたのは、
画像を見るツールを持っていたからだ。lagent の Phase 1 スコープは
`view_image` を落としていたので、Gemma には経路も、画像が無いという信号も
無かった。

つまり穴は 3 つ: ドロップの慣習を読まない、プロジェクトや作業ディレクトリ
内の画像（MCP のスクリーンショットツールの出力など）をモデルが見る手段が
ない、添付に失敗した参照は操作者には報告されるがモデルには報告されない。

## Decision

1. **素の画像パスは添付する。** `mention.Refs` は `@` 参照に加え、`@` 無しで
   書かれた画像拡張子で終わる絶対パスまたは `~` パスを取る: 文頭、または
   空白か開き記号（引用符、バッククォート、括弧）の後で始まり、空白か
   停止記号で終わり、バックスラッシュでエスケープされた空白は空白として
   読む。`@` 参照もエスケープを受け付ける。素で取るのは画像だけ — 散文中の
   テキストファイルのパスは言及であり、画像のドロップは操作者の意図で、
   画像には既にプロジェクト外からの取り込みを許す操作者入力の例外がある。
2. **`view_image` を戻す。** 移植元の組込ツールをそのまま: 読み取り専用、
   プロジェクトと作業ディレクトリに閉じ、バイトを検査する。agent はツール
   結果にピクセルを添付し、バックエンドはそれをその結果に続く image part と
   して送る。system プロンプトがこれを名指しし、MCP 取り込みの注記はサーバが
   保存した画像についてこれを再び指す。
3. **添付されなかった参照はモデルに伝える。** agent は `mention.Expand` が
   報告した問題ごとに kind `missing` の添付を加え、送信時に nonce タグの外へ
   `[not attached: <ref> — <reason>]` として描画する — lagent の言葉で、
   ファイルについて述べ、ファイルの内容は決して含まない。操作者への警告は
   不変。

## Consequences

- ドロップされたスクリーンショットは最初のリクエストに添付 1 つとして乗り、
  ツール呼び出しも、操作者ファイルの複製も削除も要らない — 移植元が
  1 点目を採れば、どちらのランタイムでも。
- Phase 1 のツール一覧は組込 9 つ。RFP の 8 つの一覧はこの記録で修正される。
  ADR-0002 は無関係（view_image はプロバイダ機能ではない）。
- ファイルが無いと伝えられたモデルは、そう言える。Gemma 4 がそうするかは
  次の計測項目で、ランタイムの役目は不在を沈黙ではなく会話中の事実にする
  ことである。
- テキストファイルの素のパスは今も何も添付しない。それらの経路は `@` の
  まま。

## Alternatives considered

- **素のパスを何でも添付する** — 却下: 散文中のパスはありふれていて、
  誤って添付されたディレクトリや大きなファイルは操作者が頼んでいない
  コスト。画像はドロップの慣習が背後にある場合である。
- **`view_image` を戻さず添付に頼る** — 却下: モデルには添付する手段が無く、
  セッション中にツールが保存した画像（MCP のスクリーンショット）に届かない。
- **操作者の文を書き換えて `@` を足す** — 却下: 打った文は打ったまま記録され
  表示される。参照は見つけるものであって挿入するものではない。
