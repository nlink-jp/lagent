# ADR-0035: プロジェクトは綴りではなくディレクトリである

| Relates to | ADR-0034（これを見つけた計測） |

## Context

lagent はプロジェクトごとに保つものを、すべてプロジェクトのパスの文字列で
引いている: transcript の `project` フィールド（再開と `lagent sessions` が
これで絞り込む）、状態ディレクトリの `.project` 印、`policy.toml` の
`[projects."<path>"]` 表 — 信頼、内容の固定、プロジェクトごとのツールと
コマンドの許可リスト。

その文字列は `os.Getwd` から来ており、`os.Getwd` は `$PWD` が現在の
ディレクトリを指していれば `$PWD` を返す。濁点を含む日本語のパスには 2 つの
Unicode の綴りがある: 合成済み（NFC、入力メソッドが打つもの）と分解済み（NFD、
このクラウドストレージがディスク上に作ったもの）。macOS はどちらも同じ名前として
扱う。APFS 上で、それぞれの綴りで作った使い捨てのディレクトリに、それぞれの綴りで
入って測った:

| | NFC で入った | NFD で入った |
|---|---|---|
| `stat` | 見つかる | 見つかる |
| `os.Getwd`（`$PWD` に従う） | NFC | NFD |
| `syscall.Getwd`（カーネル） | ディスク上の綴り | ディスク上の綴り |
| `filepath.EvalSymlinks` | 与えた綴りのまま | 与えた綴りのまま |
| もう一方の綴りで書いた Seatbelt の `subpath` 規則 | 一致する | 一致する |

つまり同じディレクトリが、運用者のシェルがどう辿り着いたかによって 2 つの
プロジェクト文字列になった。失敗したセッションの記録は NFD（121 バイト）で、
後から NFC で打った `cd` は 115 バイトになった:

- `--resume` が拒否した: 「session … belongs to <path>, not <path>」。
- 状態ディレクトリの印が、2 つ目の綴りをパスのエスケープの衝突として拒否し、
  セッションは作業ディレクトリなしで走った。
- 一方の綴りで記録した信頼・固定・許可リストは、もう一方では見つからない:
  プロジェクトは信頼を再び尋ね、運用者の以前の判断は黙って消える。

サンドボックスは影響を受けない: Seatbelt は綴りをまたいで一致する。

## Decision

1. **プロジェクトのパスはカーネルから取る。** 現在のプロジェクトを決める
   コマンド（`lagent`、`sessions`、`trust`、`workdirs`）はすべて、作業
   ディレクトリを `$PWD` ではなくカーネル（`syscall.Getwd`）から取り、これまで
   どおりシンボリックリンクを解決する。綴りはディスク上のものなので、シェルが
   どう辿り着いても同じになる。アーキテクチャテストはモジュールのコードの
   どこでも `os.Getwd` を拒否するので、`$PWD` を持ち込む 2 つ目の読み手は現れない。

2. **記録されたプロジェクトのパスは、同一性で現在のものと照合する。** 記録された
   パスを現在のプロジェクトと比べるところ — transcript の `project`（再開、
   セッションの一覧）、状態ディレクトリの印、`policy.toml` のプロジェクトの表 —
   では、文字列が等しいか、そうでなければ両方が存在して同じディレクトリである
   （`os.SameFile`）とき一致とする。これを 1 つの関数が行い、すべてが使う。
   この変更より前にどちらの綴りで書かれた記録も見つかり、ディスク上の何も
   書き換えない。

3. **書き込みはすでにある項目へ行く。** 現在のプロジェクトについての
   `policy.toml` の変更は、綴りがどうであれ、すでにこのディレクトリを名指している
   表に入るので、1 つのディレクトリが 2 つの表を持つことはない。

## Consequences

- 再開、状態ディレクトリ、信頼、許可リストは、パスがどう打たれ補完されても、
  1 つのディレクトリについて一致する。
- 同一性は、大文字小文字を区別しないボリュームで大文字小文字だけが違う綴りにも
  一致する。そこでもそれは同じディレクトリである。
- ディレクトリがもう無い記録済みのパスは、これまでどおり文字列でだけ一致する。
- パスのエスケープの衝突の判定は、異なるディレクトリをこれまでどおり分ける:
  同じ状態ディレクトリ名にエスケープされる 2 つのプロジェクトは別のファイル
  なので、一致しない。
- `policy.toml` の記録済みプロジェクトそれぞれの `stat` は、完全に同じ文字列が
  無いときにだけ払う。

## Alternatives considered

- **すべてのパスを文字列として NFC（または NFD）に正規化する。** 却下: Unicode の
  正規化表（`golang.org/x/text/unicode/norm` を直接の依存として）が要り、
  大文字小文字を区別しないボリュームとはやはり食い違い、どちらの形もディレクトリの
  半分ではディスク上の綴りと食い違うので、運用者に見せるパスやサンドボックスの
  プロファイルに書くパスが、システムの報告するものと違ってしまう。
- **読み込み時に既存の記録を正本の綴りへ書き換える。** 却下: 読み取りの問題を
  直すために運用者のファイルを書き換えることになり、transcript は起きたことの
  記録である。
- **カーネルの綴りだけにし、同一性で照合しない。** 却下: `$PWD` の綴りで
  すでに書かれた記録が、更新後に一致しなくなる — 信頼は再び尋ねられ、
  許可リストは消え、セッションは再開できない。
