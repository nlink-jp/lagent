# ADR-0003: セッション固有の事実は system プロンプトではなく会話に乗せる

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-09-10 |
| Binds | lagent |
| Decision makers | nlink-jp maintainers |
| Triggered by | 操作者の MCP サーバ 23 台を有効にすると、新セッションのたびに最初のトークンまで約 2 分待ち、操作者がそれを報告した |

## Context

ローカルサーバは参照機でプロンプトを約 580 トークン/秒で処理し、処理済み
接頭辞をキャッシュする: 直前と接頭辞がバイト同一なリクエストは約 2 秒で
始まる。操作者の global `mcp.json` は 23 サーバ・243 ツールを宣言し、
そのスキーマは 60,097 トークン — cold の接頭辞で約 2 分。

そのスキーマで実測（2026-09-10）:

| リクエスト | 最初のトークンまで |
|---|---|
| cold | 136 秒 |
| 同一接頭辞の再送 | 2 秒 |
| system メッセージ先頭の 1 行を変更 | 119 秒 |
| system メッセージ末尾の 1 行を変更 | 118 秒 |
| 代わりに 2 つ目の `system` メッセージを追加 | 118 秒 |
| 同じ行を user メッセージへ移動 | 2 秒 |

チャットテンプレートはツールスキーマを system 文の後に描画し、2 つ目の
system メッセージは同じターンに畳み込まれるので、system メッセージ内の
セッション固有のバイトが 1 つでもあれば全スキーマを再処理する。移植元
gem-agent のプロンプトはそのバイトを 3 つ持つ: untrusted-data タグ名
（セッションごとの nonce）、セッション作業ディレクトリ（セッション id を
含むパス）、セッション開始日。よって新セッションのたびに 2 分丸ごと払い、
`/clear` でもう一度払っていた。

## Decision

system プロンプトはセッションをまたいでバイト同一とする。セッション固有の
ものは全て、ランタイムの冒頭メッセージとして会話に乗せる。

- `Agent.AnnounceSession(facts)` は `session.FactsPrefix` で始まる user
  ロールのメッセージを追記する。隔離タグを名指しし（`<name> … </name>;
  このセッション固有`）、呼び出し元が渡す事実 — 作業ディレクトリとその
  使い方の注記、開始日（`cmd.sessionFacts`）— を載せる。
- lagent が書いたものなので包まずに送り、他のメッセージ同様 transcript に
  記録されるので、再開したセッションも再生する。呼ぶのは `agent.New` の後、
  `SetHistory` の後（タグは新しく、復元した履歴自身の冒頭メッセージは旧
  タグを名指ししている）、`/clear` の後 — 回転した作業ディレクトリは
  system プロンプトの再構築ではなく新しい事実メッセージでモデルに伝える。
- system プロンプトはそれらの事実がどこにあるか（「会話冒頭のランタイム
  事実メッセージ」）だけを言い、それ以上は言わない。`{{DATA_TAG}}` は
  無くなった。
- セッション一覧は事実メッセージをプレビューにも会話ありにも数えない
  （`session.FactsPrefix`、ShellContextPrefix の先例）: それだけを記録した
  transcript は `--continue` に飛ばされ、再開ヒントも出ない。
- `cmd.TestSystemPromptIsIdenticalAcrossSessions` が不変条件を固定する。
  `rotateWorkDir` は `setSystem` の代わりに `announce` コールバックを取る。

これが生む連続した user メッセージ（事実、次に操作者の初手）は LM Studio の
テンプレートに受理され、モデルは事実から作業ディレクトリを読み取ることを
実測した。

## Consequences

- サーバのキャッシュが接頭辞を保持している間 — 同じプロセス、同じツール
  一式、同じ指示ファイル — 新セッションと `/clear` は数秒で始まる。サーバ
  再起動後の最初のセッションは cold のコストを 1 回だけ払う。
- 事実は全リクエストの先頭ではなく 2 番目になる。計測した全ターンでモデルは
  それを読み、transcript では会話の先頭に見える。
- 日付は従来どおりセッション開始時。長いセッションの「今日」は従来どおり
  ずれる。
- 接頭辞は system プロンプトとツール一式だけに依存するようになったので、
  残る手段はツール一式そのもの: `[mcp].exclude`、または RFP が Phase 2 に
  残した MCP の遅延目録。

## Alternatives considered

- **2 つ目の system メッセージ** — system ターンに畳み込まれると実測: 118 秒。
  却下。
- **作業ディレクトリの固定エイリアスパス**（`…/work/current`）— パスは
  揮発集合から外れるがタグと日付は残り、同一プロジェクトの 2 セッションが
  1 つのリンクを奪い合う。却下。
- **セッションをまたいで固定のタグ** — nonce はツール結果が自分の閉じタグを
  偽造できないために存在し、`guard.Wrap` は名前を含む内容を拒否する。
  永続化した名前は攻撃者が名前を知る窓を広げ、事実メッセージが既に与える
  もの以上の利得がない。却下。
- **nonce で包んだデータ添付としての事実** — 添付が自分を包むタグを名指し
  する必要があり、`guard.Wrap` はそれを拒否する。却下。
