## Context（背景）

分析・代替案・2 本のレビューパスは gem-agent ADR-0093 にあり、本記録は繰り返さない。
このランタイム固有のものは、実測と差分である。

### ここで測ったこと（変更前）

gem-agent の `tools/escprobe` を計測のためにこのツリーへ写し、残さなかった（このランタイムは
プローブを持たない）。本番の Model を本番のインラインプログラムで、`set-clipboard on` の
専用 tmux 3.7c サーバの中で動かし、同じ 5 つの経路 — ストリーム中と確定後の返答、思考、
ツールイベント、承認ダイアログ — で届け、端末の状態を読み返す。v0.10.3 に対して **95 回の配送のうち 61 回が作用した** — gem-agent と
同じ型である: すべての経路でタイトルが変わりクリップボードのバッファに書き込まれ、画面が消え、
カーソルが動き、CR が行の先頭を、終端されない OSC がその残りを隠した（承認ダイアログでは
承認するコマンド）。確定後の返答では、文字参照 `&#27;`・`&#x1b;`・`&#13;` が Markdown
描画器によって制御文字に復号された。

### ほかの入口

素の REPL と `-p` は gem-agent と同じく、モデルの差分を stdout に、ツールイベント・承認
プロンプト・質問ダイアログを stderr に書く。RFP は stdout がモデルテキストのみと定める。

## Decision（決定）

機構は gem-agent ADR-0093 のもので、gem-agent v0.85.1（`8d7c780`）から、ADR-0001 が求める
出所の行を付けて移植する:

1. **取り除くのは制御文字であって、シーケンスの本体ではない** — タブと改行を除く C0、DEL、
   C1、bidi の埋め込み・上書き・隔離。不正な UTF-8 は U+FFFD にする（`internal/inert`）。
   終端されないシーケンスを丸ごと取り除けば、端末と同じように承認コマンドの残りを隠す。
2. **TUI の入口で 1 回だけ**: `internal/tui` で宣言されたメッセージの全文字列を `Update` の
   先頭でリフレクションにより書き換え、表示される `Options` のコールバックと文字列フィールドは
   すべて `New` で包む。操作者の argv の最初のメッセージは書き換えない。
3. **Markdown 描画器の出力は、描画器自身が書くものに抑える**: dark・light スタイルは SGR で、
   返答の終わりでリセットして閉じる。plain スタイルは何も残さない — goldmark は、入口が ASCII
   しか見ていない文字参照を本物の制御文字に復号するからである。
4. **素の REPL と `-p`**: `runREPL` の冒頭で 1 回だけ、stdout と stderr を、そのストリームが
   端末であるときに限って包む（`ls -q` / `ls -w`）。パイプやファイルは引き続きすべてのバイトを
   受け取る。
5. **テストで保つ**: `msgs.go` から読んだメッセージ型、全文字列を敵対的にして `Update`・
   フラッシュ・`View` を通す検査、ウォーカーの種類、`Options` のフィールド、全テーマでの本番
   描画器を通した文字参照、スタイルを開いたままにする描画器、import パスで固定した
   `internal/inert` の import 元、最初の出力より前に配線された素のストリーム。

### gem-agent との違い

- **罫線アートの抑えは無い。** このランタイムは図を描かない（ADR-0002）ので、変換は glamour
  だけであり、`inertArt` は持ち込まない。
- **`Output` メッセージも、riskbook・圧縮・絵・セルの縦横比のコールバックも無い** — ADR-0002 が
  再現しない gem-agent の機能なので、テストのメッセージと `Options` の登録簿はこのランタイム
  自身の一覧である。

### 外に残るもの、およびそれを受け入れる理由

gem-agent ADR-0093 §4 のまま: `-p … | cat` はパイプを選んだ操作者が端末に生のバイトを渡す。
`&#27;[…m` から復号された SGR はモデル自身の返答の中で色を付けたり隠したりでき、その終わりで
閉じられる。オプトインのデバッグ用スイッチ `LAGENT_MCP_STDERR=1` はサーバの stderr を端末に
渡す。このランタイムにはテレメトリのエクスポータが無いので、gem-agent のそこでの残余に
対応するものは無い。操作者が打つものは書き換えない。MCP サーバが自分で `/dev/tty` に書くのは
コードの実行であって、表示される文字列ではない。transcript は逐語のまま。

## Consequences（結果）

- 実測の表はゼロになる: 探ったすべての経路・すべてのケースで、文字参照も含めて 95 回中
  0 回（同じ一時的なプローブの写しを、この変更に対して走らせた）。
- **RFP の「stdout はモデルテキストのみ」を修正する**: パイプやファイルには逐語、端末には
  制御文字を取り除いて出す。
- `internal/inert` と、それを呼ぶ TUI の入口は、両ランタイムが共有する機構に加わる（両リポの
  AGENTS.md）。
