# ADR-0010: 自動承認のモデル層は採らない

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-09-12 |
| Binds | lagent |
| Decision makers | nlink-jp maintainers |
| Triggered by | RFP の Phase 2 はモデル層を「採用前に計測する」項目に挙げる。ベンチはそれが裁いたはずのものと、ローカルモデルがそれに課す代価を計測した |

## Context

gem-agent の自動承認階梯は 2 層ある。規則層は呼び出しをそれが何であるか —
シェルが宣言したレーン、ツールが名指すファイル、MCP サーバのツールか — で
Safe、Review、Block に分類する。モデル層は `--auto` 下の Review 層の全呼び出し
を取り、操作者の rulebook と呼び出しの引数をペイロードに 2 つ目のモデルへ
尋ね、承認・エスカレーション・ブロックを決める。gem-agent はその層が Vertex AI
で判定ごとに 2〜11 秒かかることを計測し、4 秒未満に保つために専用のモデル
スロットへ移した（gem-agent ADR-0082）。

lagent は規則層だけを出荷した（ADR-0002、RFP §3:「Phase 2 で採用前に計測」）。
`AutoDecision.ModelConsulted` はレコード互換のため常に false。以来 Phase 2 が
計測したもの:

- **層が裁いたはずのもの。** ベンチの 6 タスクに対するベースライン 36 実行
  （ADR-0006、2026-09-12 の実行）で、規則層は 18 実行あたり 22 の自動判定を
  した。18 は Safe で走り、4〜5 が Review — すべて write レーンの `shell_exec`
  で、すべてモデルが read レーンで走らせられた（他の実行では実際に走らせた）
  検証の `go run`。MCP 呼び出しが Review に達したことは無く（ベンチのサーバは
  操作者の lookup サーバ同様に `"never"` ポリシーを持つ）、ファイル書込も無く
  （プロジェクト内の編集は Safe）、Block も起きなかった。one-shot ではその
  Review 呼び出しは拒否され、それでも全実行が完了した。対話中なら 1 回ずつ
  プロンプトが出たはずである。
- **ここでの代価。** モデル層の判定は同じローカルサーバへのもう 1 リクエスト
  で、接頭辞が違う（会話ではなく risk プロンプト）ので、メインループが乗る
  接頭辞キャッシュには乗らない: 実測 580 tok/s で約 1.5〜2k トークンの
  プロンプト処理と JSON 判定 — 基準機で判定ごとに 3〜5 秒、その間メインの
  ターンは待つ。判定に thinking を on にすれば（ADR-0009 の代価計測）10 秒に
  なる。gem-agent の 3.65 秒という下限は 2 つ目の小さなモデルから来ている。
  lagent はモデル 1 つで、2 つ目のスロットは無い。
- **誰が裁くのか。** ローカルモデル 1 つでは、層は提案者が自分の提案を評価する
  ことになる — gem-agent ADR-0020 §4 が memory ファイルについて挙げ、ADR-0082
  が別モデルで答えた異議。規則層は意図を読むためにコマンド文を読まないと
  意図して決めている（gem-agent ADR-0073: レーンが決める）。モデル層はそれ
  以外を読まない。

Review 層の呼び出しに対する操作者の手段は既にあり、判定より安い:
決めたツールに対する `[approval.tools]` の `"never"` 行、1 実行分の `--allow`、
inspection と検証がそもそも Review に達しないよう ADR-0008 が真にした read
レーンの事実。モデル層に残る価値 — 操作者がまだ決めていない write レーンの
コマンドの呼び出しごとの判断 — は、ベンチが一度も必要としなかったもの
である。

## Decision

モデル層は**採らない**。RFP の Phase 2 項目は保留ではなく計測による却下で
閉じる。階梯は今のまま: Safe は `--auto` 下で走り、Review は操作者に尋ね
（無人なら ADR-0008 が与える経路とともに拒否）、Block は常に尋ねる。
`ModelConsulted` は gem-usage-lens のレコード互換のため false のまま。

本記録を再び開く条件は意見ではなく計測: ベンチ上のあるタスク種別で、操作者
なら承認したはずの Review 呼び出しが無人実行の完了を妨げ、かつ
`[approval.tools]` の行やレーンの事実がそれを除けないこと。その数は
ベンチの `gate_decision` と `auto_decision` レコードから出す。

## Consequences

- Phase 2 の承認まわりの作業は完了: 2 つ目のモデル呼び出しも risk プロンプトも
  rulebook ペイロードも、gem-agent と歩調を合わせるべき判定スキーマも無い。
  判定階梯はアーキテクチャテストが固定する 1 関数
  （`internal/agent/decision.go`）のまま。
- 操作者が事前承認していない write レーンのシェルを要する無人実行はそこで
  止まり、そう言う。それがこのランタイムの one-shot 利用の天井で、提案者が
  書いた判定で塗り潰すのではなく、述べておく。
- ADR-0002 のモデル層の行は今日「Phase 2」と読める。本記録がその結果で、RFP
  の Phase 2 一覧にはここを指す注記が付く。

## Alternatives considered

- **gem-agent の層をそのままメインモデルで採る。** 却下: ターン全体がしばしば
  10 秒のランタイムで Review 判定ごとに 3〜5 秒、裁くのは提案者、対象は
  ベンチが操作者の行とレーンで既に覆われていると示した呼び出し。
- **層のための小さな 2 つ目のモデル**（gem-agent ADR-0082 の対処）。今は却下:
  基準機で 26B の隣に 2 つ目のモデルを載せるのはメインモデルが要するメモリ
  で、ベンチはそれが下すべき判定を 1 つも生んでいない。再開の計測が来たら、
  最初に測るべき形はこれ。
- **write レーンの検証コマンドをパターンで承認する**（`go test`、`go vet`）。
  却下: 「検証」はコマンド行の単語であってレーンではなく（gem-agent
  ADR-0073）、ADR-0008 が必要を無くした — それらのコマンドはモデルが宣言
  すれば read レーンで無承認に走る。
