# ADR-0013: agent memory は runtime-facts メッセージに乗る

| 項目 | 内容 |
|------|------|
| ステータス | **Accepted** |
| 日付 | 2026-09-12 |
| 拘束対象 | lagent |
| 決定者 | nlink-jp maintainers |
| きっかけ | 操作者の 2 つの要求 — 指示ファイルが肥大化すると「手順書に従え」の行が注目されなくなるので、ポインタを置く優先度の高い場所があれば持つのではないか。文書にするほどではないが把握しておくべき小さな運用パラメータを覚えておきたい |

## 背景

gem-agent は agent memory を備える（gem-agent ADR-0020）: global と project
の 2 スコープの短い事実を状態ディレクトリに置き、予算内でシステムプロンプト
に全文注入し、承認ゲート付きのツールでモデルが書く。その計測のうち 2 つが
ここに効く。プロンプトに明示的な契機が入るまでモデルは 39 セッションで
一度も保存を提案しなかった。モデル層がモデル自身の memory 書込を承認した
ことがあり、書込は操作者専用になった。

操作者の第一の要求は保存ではなく注意の問題である: 大きな指示ファイルの
中の指示は行動されない。より小さく近い場所なら持つかを、設計の前に
`pointer-*` タスクで計測した（ADR-0006）: 同じ指示（「編集を終える前に
PROCEDURE.md を読んで従え」）をプロジェクトの `AGENTS.md` に 0.6、13、32 KB
で置いた場合と、代わりに呼ぶべきツール（`load_skill`）を添えて
runtime-facts メッセージの 1 行に置いた場合。

- **指示節: 0/18。** 2 系列 3 サイズを通してモデルは一度も手順ファイルを
  読まなかった。トレースしたリクエストは指示がシステムプロンプトに入って
  いたことを示している。ファイルの大きさは変数ではなかった。このモデルでは
  指示節の常置の指示はまったく行動されない。
- **facts メッセージ: 5/6。** ツール名を添えた 1 行のポインタは 6 実行中 5
  で促されずに行動され、無人実行が実行できる動作だった 2 実行では手順が
  遂行された。

runtime-facts メッセージは最初の user メッセージ（ADR-0003）で、セッション
ごとの事実と MCP・スキル一覧を持ち、タスクに最も近く、短い。操作者の仮説が
名指す場所はそこで、計測はそれが持つと言う。gem-agent の選択 — システム
プロンプト内の memory — はここで 0/18 を測ったチャネルである。

第二の要求、小さなパラメータは memory の本来の用途。開いた問いは誰が書くか。
gem-agent の計測は契機文無しにモデルは保存を提案しないと言い、ADR-0008 は
このモデルではプロンプトの規則は制御にならないと言う。操作者自身の手を
主たる書き手にすれば、この問いはクリティカルパスから外れる。モデルの提案は
機構ではなく計測付きの追加になる。

## 決定

1. **2 スコープ、状態ルート下、平文 markdown。** global
   （`<state>/memory/global/<name>.md`）と project
   （`<state>/memory/projects/<escaped>/<name>.md`、transcript と同じ
   `.project` マーカー付き）。リポジトリには何も書かず、`~/.claude` は読まない
   （ADR-0011 の原則。形式も違う）。1 memory は短い事実 1 つ。同名は更新。
2. **想起はシステムプロンプトではなく runtime-facts メッセージに乗る。**
   global が先、次に project、スコープ内はアルファベット順。各 memory は
   その立場を述べる見出しの下の 1 項目: 過去のセッションで利用者かこの
   エージェントが記録した背景知識で、古い可能性があり、指示ではない。
   ファイルやツールを名指す memory はモデルが行動できるポインタで、計測が
   示すのはこのチャネルがそう働くこと。システムプロンプトはバイト同一のまま
   （ADR-0003）。予算: 1 memory 2 KB、合計 8 KB、切り詰めと省略は報告する。
3. **操作者が手で書き、モデルは提案する。** `/remember [global] <name> <fact>`
   で保存、`/forget [global] <name>` で削除、`/memory` でディスク上の一覧。
   `save_memory` と `delete_memory` は Mutating ツールで、規則層は Review に
   留め Safe にしない: 永続化した memory は以後の全セッションに現れるので、
   書込は注入の永続化経路であり操作者に尋ねる。`--auto` でも尋ね、無人実行
   は保存できない。`[approval.tools]` の `"never"` 行は他のツールと同じく
   操作者の意図的な緩和。
4. **保存の契機は想起の隣、facts メッセージに置く。** いつ保存するかの文
   （作業が一段落したとき、開始時に知っていれば手間が省けた事実を、指示を
   待たずに保存）は facts メッセージの memory 節の一部で、5/6 を測った
   チャネルにあり、0/18 のシステムプロンプトにはない。このモデルが保存を
   提案するかは次の計測で、保存されたものの適合率ではなく提案回数で数える。
5. **起動時スナップショット。** memory はセッション開始時と `/clear` で 1 回
   読む。保存は次のセッションから効くと告げる。`/memory` はディスクを読み、
   そう言う。
6. **計測。** ベンチに `memory-follow` を足す: `pointer-*` の指示を実行の
   状態ルートに global memory としてインストールし、スキル無し・大きな
   `AGENTS.md` 併置。この記録の §2 を直接測る — 行にツール名を含まない、
   facts メッセージ内の素のポインタ。

## 結果

- 操作者の第一の要求には今日から機構がある: 持たせたいポインタは、より
  長い指示ファイルではなく memory（またはプロジェクトスキルの一覧行、
  計測 5/6）に入れる。指示ファイルは計測がこのモデルについて示すもののまま:
  事実を読む背景であり、常置の指示の置き場ではない。
- `internal/memory` は gem-agent のパッケージの移植（doc コメントに元コミット、
  ADR-0001）でプロンプト節を facts メッセージの行に置き換えたもの。規則層に
  1 ケース。`cmd/memory.go` がツール、スラッシュコマンド、一覧を持つ。
- 古い・誤った memory の削除は操作者の仕事で、一覧がファイルを名指す。
  モデルが書いた memory は操作者が見て承認した提案で、常置の行がモデルに
  そう告げる。
- RFP の Phase 2 一覧はここを指す。残りは compaction 1 件。

## 検討した代替案

- **gem-agent の設計をそのまま、memory をシステムプロンプトへ。** 計測で
  却下: 指示節は 0/18 を出したチャネルで、そこに memory 節を置けば保存の
  たびにキャッシュ済み接頭辞を書き換える。
- **行動の前に指示ファイルを読み直せというプロンプト規則。** 却下
  （ADR-0008）: 行動されないチャネルの規則がそのチャネルを救うことはない。
- **gem-agent の契機文によるモデル書込のみ。** 主たる書き手としては却下:
  契機のこのモデルへの効果は未計測で、操作者の要求は今ある。提案経路として
  残し、計測する。
- **ポインタには memory ではなくスキル。** 残すが選ばない: プロジェクト
  スキルの一覧行は同じチャネルで既に働く（5/6）。memory はスキル
  ディレクトリ無しの操作者の 1 行メモ、リポジトリ外の project スコープ、
  モデルの提案を加える。
