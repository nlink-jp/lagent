## Context

幅が縮むと、TUI は `tea.ClearScreen` を返して行カウンタを戻していた。端末の折り返し直しが、Bubble Tea が描き直しを再開する位置の上に残す入力欄の古い写しを掃除するためである。gem-agent は、それが iTerm2 と kitty で何を失わせるかを、手でも自動でもマウスのドラッグでも測った（ADR-0094）: iTerm2 は消去のたびに画面をスクロールバックへ移すので、1 回のドラッグで何百行もの空行と、通知ごとの枠の写しがそこに積もった。kitty はその場で消すので、画面上のすべての行と絵を失った。同じ ADR は、そもそも古い写しが出る理由も見つけた: 入力欄は幅いっぱいまで埋めて描かれており、ライブのリサイズ中の描き直し — カーソルの点滅だけでも — が画面より幅広く届いた。端末は通知した幅より先に進むからである（iTerm2 は画面を連続して動かしつつ、通知とカーネルのウィンドウの大きさは約 200 ms ごとにしか更新しない）。

ADR-0025 はこのランタイムについてこの制限を記録し、gem-agent と一緒に直すとしていた。

## Decision

gem-agent が採った 3 つを、そのままの形で:

- **C. 縮小時に消すのは枠の行であって、画面ではない。** プログラムは `tui.SweepWriter` を通して書く。縮小時、モデルは K — 描かれた枠が折り返しで増やした行数 — を求め、writer は描画器の次の書き出しを K 行上へ延ばしてその下を消す。カウンタは消した行数に合わせる。writer が無ければ何も消さない。
- **D. 枠の行は文字の長さにする。** 管理領域のビューのすべての行を、最後に見える文字で終わらせる（`shortRows`）。背景つきの埋め草はその背景のまま行末まで消す指示になるので、入力行のハイライトは今もウィンドウいっぱいに伸びる。入力欄のカーソル（反転表示の空白）は残す。
- **E. リサイズの最中は枠を狭く描く。** 幅を変える大きさの通知から、通知が 400 ms 来なくなるまで、枠のすべての行を `minWidth − 1` 桁に切り詰める。落ち着きの合図で完全に描く。高さだけを変える通知では何も起きない。

`internal/tui/sweep.go` と `shortrows.go` は、それらを採った gem-agent のコミットから移植し、`Update`/`View` の変更も同じである。

移植しないもの: writer の測定用の面 — 記録、構えごとの記録、`Inject` と `DrawnCells` — は、gem-agent の `resizeprobe` だけが読む。このランタイムにはプローブが無く（`tools/` が無い）、誰も呼ばないメソッドは誰も確かめない面である。`Stats` はテストが読むので残す。

## Consequences

- 最初の枠の後に画面を消去することは無くなった。ADR-0025 の既知の制限は解決し、CHANGELOG にそう書く。
- ADR-0020 の勘定は変わらない: `emitSegments`・宣言した行数・`physicalRows` は変更せず、C はカウンタを自分が消した行数に合わせるだけで、D が短くするのは管理領域のビューであって書き出すものではない。
- ウィンドウの幅が変わっている間、枠のすべての行 — 入力欄・フッタ・ダイアログ・流れている応答の末尾 — は、最後の大きさの通知から 400 ms、19 桁で切って描かれる。
- gem-agent ADR-0094 が記録する残りと範囲は、ここでもそのまま当てはまる: 測ったのは iTerm2・kitty・tmux だけ。背景色つきで消したセルを中身として数える端末や、折り返し直さずに切り詰める端末では、古い行が残るか、履歴の行が消えうる。マイクロ秒の競合で 1 回の縮小の K が誤りうる。
- gem-agent と同じテストがここでもそれを守る: 本物の描画器の書き出しが、掃除が書き換えるカーソル上移動で始まること、K が枠の折り返しの増分であること、後の構えが前の構えを置き換えること、最後の通知が落ち着くまで枠が狭いこと、カーソルのセルとハイライトが短くしても残ること、最初の後の大きさの通知が画面を消去しないこと。
- gem-agent で測り、ここでは測り直していない: 機構も描く枠も同じコードである。運用者が、このランタイムの組み立てた本体（`v0.11.0-5-g14b81c0`、2026-09-29）で、iTerm2 と kitty、画面に `/show` の絵を出して手で確かめた: 絵は残った、古い入力欄は残らなかった、スクロールバックに空行は入らなかった、広げ直しても問題なかった。mermaid の絵はこの確認に含まれていない。

## Alternatives considered

- **lagent が自分で測るまで消去を残す。** 却下: 測ったのは端末と、ここと同一のコードであり、消去の損失は両方の端末で測った。
- **測定用のメソッドも移植する。** 上で却下した: ここでは誰も呼ばない。
