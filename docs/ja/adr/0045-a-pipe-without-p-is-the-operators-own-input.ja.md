# ADR-0045: `-p` なしのパイプは操作者自身の入力であり、監査の 2 つの限界を受け入れる

| 項目 | 値 |
|-------|-----|
| Status | **Accepted**（2026-11-09） |
| Date | 2026-11-09 |
| Binds | lagent |
| Decision makers | nlink-jp maintainers |

| Relates to | gem-agent ADR-0023（プロジェクトの信頼）、ADR-0041（パスは行き着く先で判定する） |

## Context

gem-agent の監査が挙げた 3 点は、このランタイムにも当てはまる。ランタイムは聞かずに走るものを守り、承認や操作者の行為が要るものは残余として記録する。

## Decision

1. **`-p` なしのパイプは操作者自身の入力のままとする。** 素の REPL は打鍵と同じ経路で読むので、中の `!` とスラッシュコマンドは実行され、テキストはターンの指示になる。操作者がパイプを組まない限り何も走らず、`curl … | bash` と同じ形なのでゲートしない。README にそう書き、第三者のテキストはデータとして添付する `-p` に渡すよう書く。
2. **祖先の指示ファイルは信頼の確認の外のままとする。** これを読むのはドロップイン互換の動作である。コードに記された理由（クローンは自分より上にファイルを置けない）は、クローンのサブディレクトリで始めたセッションには当てはまらず、クローンの最上位の指示ファイルが祖先になる。そこで始めるのは操作者の行為で、越えるのは指示の文だけである。
3. **ファイルツールの判定と書き込みは、違うリンクを見ることがある。** ルート内のディレクトリを判定と書き込みの間にリンクへ差し替えると、直接の呼び出しなら拒否される `.git` や `.claude` への書き込みが届く。成立には、以前に承認された write レーンのコマンド、走り続けるバックグラウンドの子、その間に合わせた変更が要る。この前提条件から受け入れる。

## Consequences

- 動作は変わらない。

## Alternatives considered

- **`-p` なしのパイプを拒否する** — gem-agent が実装し、リリース前に取り下げた: 操作者自身が行う行為を守るために、スクリプトの使い方を壊すことになる。
