## 背景

ADR-0052 §1 は線を引いた。サンドボックスが相手にするのは、モデルが間違って、または誘導されて実行したコマンドで、ランタイムと競争するように書かれたプログラムではない。操作者が指示したものは、指示されたという理由で残した。だがその指示はどれも、直し方は言うが、誰が起こせるのか、どのくらい起きるのか、何を得るのかを言わない提案への答えだった。

コードは gem-agent と同じものの移植で、読み方も同じである。起点は、**A** 読んだ文章に誘導されたモデル（守る）、**B** 信頼される前のリポジトリの中身（守る。信頼の記録で）、**C** 操作者自身の操作（攻撃ではなく正しさの問題）、**D** ランタイムと競争するプログラム（守らない。ADR-0052 §1）、**E** 操作者の権限で動くマルウェア（守らない）。変更ごとの照らし合わせは gem-agent ADR-0123 にある。

**訂正。** ADR-0051 §8 は、scratch のプローブの固定名の下にリンクを置くと、そのリンク越しに `x` が書かれると書いた。プローブのコマンドは read レーンで走るので、書き込みが届くのは read レーンがもともと書ける場所だけである。

## 決定

1. **指摘は、何かを作る前に判断する: どんな条件で、どのくらい起きるか。誰が起こすか。その者はすでに何を持つか。それで新しく何を得るか。** 修正はこの 4 つの答えを添えて提案し、「直さない」を選択肢に入れる。この 4 つなしの提案に応えた指示は、この 4 つで判断し直す。

2. **プロジェクトのスキルを、使う時点では比べない**（ADR-0049 を置き換える）。起点は C、または pull を通した B。上流の作者はプロジェクトのコードをすでに書いている。変わった文章は次の `/clear` か起動までモデルに届き、そこで比べられる。その文章が導くコマンドも、レーンと承認を通る。外すもの: 使う時点の比較、問いとその結果、無効化の状態、`tools.NeedsOperator` とエージェント側の扱い、問いのダイアログの見出しと初期選択、素のプロンプトでの単語による答え、ターンの一段としての `/skill`、スキルの信頼の記録、エントリか解決先のパスに制御文字や書式文字を含むスキルを一覧に出さない規則（端末のストリームと TUI が入口で文章を無害化する。ADR-0024）。

3. **スキルの digest は、v0.27.4 が出した走査で取る。** ファイル数 2,000 の上限はそのまま。エントリ数と深さの上限、階層ごとのハンドルは外す。gem-agent ADR-0123 が挙げる 10 の木で比べた。ピンと注記は前後ですべて同じで、digest は gem-agent と同じ値だった。例外は 40 段の深さのスキルだけで、v0.28.0〜v0.30.0 は 32 段で打ち切っていたが、今は木全体を digest する。その頃にそれをピンしていれば、次の起動で一度だけ尋ねる。

4. **open は標準ライブラリのものに戻す**（ADR-0050 を置き換える）。v0.27.4 のとおりで、トレースのファイルとルールブックも含む。外すもの: `bounded` の open の補助と、open のテスト。名前の場所の FIFO は、割り込むまで open を待たせる。git は FIFO を運ばない。残すもの: ファイルツール自身の待たない open と、読み取りの子プロセスが呼び出しの名指すルートだけを開くこと（ADR-0047）。

5. **起動時の確認は v0.29.0 の形に戻す**（ADR-0051 を置き換え、ADR-0052 §3 を撤回）。プローブは乱数名で排他的に作り、対照は同じコマンドをサンドボックスの外で走らせ、削除はパスで行う。scratch のプローブは固定名、時間の上限は置かない。クリップボードの取り込みのファイルは、乱数名で一時ディレクトリに作る。

6. **ディスク上の信頼の記録が記録である。** ポリシーファイルがそのプロジェクトのピンを持たなくなったときにセッションのピンを使い続ける代替と、セッションの書き込みでもそれを保つ `adoptPolicy`（どちらも v0.27.4 から）を外す。ポリシーファイルはどのレーンからも届かない。ファイルが無い、または解釈できないときは、これまでどおりセッションの写しを記録として使う。

7. **残すもの:** ADR-0042（承認済みのキャッシュを read レーンの外へ）、ADR-0043（`!` コマンドの出力はデータ）、ADR-0044（ダイアログは呼び出し全体を運ぶ）、ADR-0046 と ADR-0047（追加ディレクトリ）、ADR-0052 §2（レーンの基準を一度だけ決める）、v0.27.4 の、ピンをディスク上の記録と比べること。

## 結果

- 変わったスキルについての問いは出ない。セッション中に変わったスキルは、`/clear` か次の起動までは今の中身で読み込まれ、そこで外されて名前が示される。
- ランタイムが開く名前の場所に FIFO があると、割り込むまで待つ。
- README と README.ja、両言語のマニュアルとアーキテクチャのリファレンス、AGENTS.md をコードと一緒に直す。

**受け入れて記録するもの:** セッション中に変わったスキルは `/clear` か起動までモデルに届く（C、または pull を通した B）。名前の場所の FIFO は open を待たせる（承認されたコマンド、またはレーンの外）。確認の最中のプローブの差し替え（D）。深さやエントリ数でファイル数の上限を超えるスキルの木は起動を遅くする（B）。プロジェクトのピンを失ったポリシーファイルは、そのファイルをピンのないものとして読み込ませる（操作者、またはレーンの外）。

## この設計が要求するテスト

- ピンが区別する種類の木それぞれで、戻した走査の digest が、外した走査の digest と同じである（一度比べる）。
- 外すものを保っていたテストは一緒に外す。`make check` が通る。

## 検討した代替案

gem-agent ADR-0123 と同じ: 問いは残して周りだけ外す、問わずに使う時点で断る、プロジェクトのファイルを開く前に見る処理は残す、先にリリースする — どれもそこに書いた理由で採らない。
